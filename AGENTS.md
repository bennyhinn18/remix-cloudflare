# AGENTS.md — @bennyhinn18/remix-cloudflare

This guide provides instructions and architectural context for AI agents (and human contributors) working on `@bennyhinn18/remix-cloudflare`.

---

## 🎯 Repository Overview

`@bennyhinn18/remix-cloudflare` is the lightweight, high-performance Cloudflare Workers & Pages adapter for **Remix 3**.

Unlike Remix 2, Remix 3 is built directly on native Web Platform standards (`Request`, `Response`, `TransformStream`, and `createRouter`) without React or file-based magic. This package bridges Cloudflare's runtime isolate (`fetch(request, env, ctx)`) to Remix 3's fetch router.

## 📂 Project Architecture

```
remix-cloudflare/
├── src/
│   ├── index.ts        # Library public entry point
│   ├── handler.ts      # createWorkerHandler: bridges Cloudflare fetch to Remix router
│   ├── context.ts      # getCloudflareContext, cloudflareContext middleware, ContextKeys
│   ├── types.ts        # TypeScript definitions for options and bindings
│   └── cli.ts          # CLI entry: 'npx @bennyhinn18/remix-cloudflare init'
├── tests/
│   ├── adapter.test.mjs # Unit tests for createWorkerHandler and getCloudflareContext
│   └── cli.test.mjs     # Integration tests for CLI init migrations
├── dist/               # Compiled bundles (ESM, CJS, and DTS generated by tsup)
├── wrangler.jsonc      # Local testing configuration for Cloudflare Workers
├── package.json        # Package metadata, exports, bin, and scripts
└── tsconfig.json       # Strict TypeScript configuration
```

### Key Modules

1. **`src/handler.ts` (`createWorkerHandler`)**:
   - Accepts a Remix 3 `Router` instance and options (`onError`, `fallbackToAssets`).
   - Decorates the incoming `Request` with `env` and `ctx`.
   - Dispatches requests to `router.fetch(request)`.
   - Intercepts 404 responses and falls back to `env.ASSETS.fetch(request)` (Cloudflare Edge Assets).
   - Catches unhandled exceptions with optional custom `onError` boundary or 500 fallback.

2. **`src/context.ts` (`getCloudflareContext`)**:
   - Type-safe extraction helper: `const { env, ctx, cf } = getCloudflareContext<Env>(context)`.
   - Accesses Cloudflare D1, KV, R2, Vectorize, and Workers AI bindings inside Remix action controllers.

3. **`src/cli.ts` (`init`)**:
   - Scaffolds `worker.ts` with `createWorkerHandler`.
   - Generates `wrangler.jsonc` with `nodejs_compat` and edge assets.
   - Cleans `package.json` scripts (`build`, `deploy`, `preview`) and adds dependencies.
   - Refactors `app/router.ts` for edge runtime (decoupling Node-only asset servers), creating a `.bak` backup.
   - Updates `server.ts` to keep local Node development (`npm run dev`) working seamlessly.

## ⚠️ Critical Rules for AI Agents

1. **Edge Runtime Isolation**:
   - `src/handler.ts`, `src/context.ts`, and `src/types.ts` run inside Cloudflare Workers isolates (V8 sandbox).
   - **NEVER** import Node.js built-in modules (`node:fs`, `node:child_process`, `node:http`, etc.) into runtime files (`src/handler.ts`, `src/context.ts`, `src/index.ts`).
   - Node built-ins are **ONLY** permitted in `src/cli.ts` (which executes locally via Node CLI).

2. **Zero Runtime Dependencies**:
   - Keep the package ultralight. Do not add runtime dependencies.
   - Remix is a peer dependency (`peerDependencies: { "remix": "^3.0.0" }`).

3. **Always Test Before Committing/Publishing**:
   - Always run `npm test` and `npm run typecheck` after any modifications.
   - Both must exit with code 0.

4. **NPM Publishing Integrity**:
   - Package name is scoped: `@bennyhinn18/remix-cloudflare`.
   - The `bin` field in `package.json` must be `"bin": { "remix-cloudflare": "./dist/cli.js" }` (relative path with `./`).
   - Never commit `.env` or sensitive credentials to Git.
